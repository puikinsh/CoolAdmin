# Repository Guidelines

## Project Structure & Module Organization

CoolAdmin is a static Bootstrap 5 dashboard template with vanilla JavaScript and 35 pages. Author page templates in `src/pug/pages/`, layouts in `src/pug/layouts/`, and fragments in `src/pug/partials/`. Page content and inline scripts live in `src/pug/partials/content/`; navigation data lives in `_nav-data.pug`.

SCSS sources live in `src/scss/`, with `theme.scss` and `app.scss` as entry points. Root HTML and `css/theme.css` / `css/app.css` are generated, committed deliverables. Browser logic lives in `js/`; build helpers live in `scripts/`. Node regression tests live in `test/`. Assets are in `images/`, `fonts/`, and `media/`, third-party bundles in `vendor/`, and README images in `screenshots/`.

## Build, Test, and Development Commands

- `npm ci`: install locked dependencies; use Node >=22.12.
- `npm run dev`: run Pug and Sass watchers alongside Vite at `http://localhost:3000`.
- `npm run build`: regenerate minified FullCalendar bundles, HTML, and CSS.
- `npm run build:pug` / `npm run build:sass`: rebuild templates or styles.
- `npm run check`: build and run Node regression tests.
- `python3 -m http.server 8000`: preview shipped files without the Node toolchain.

Vite serves development files; production assets are generated by Pug and Sass. Commit regenerated outputs with their source changes.

## Coding Style & Naming Conventions

Use two-space indentation in Pug and JavaScript; preserve existing SCSS indentation, commonly four spaces. Follow existing JavaScript conventions: semicolons, single-quoted strings, camelCase functions, and uppercase constants. Use vanilla DOM APIs and existing utilities in `js/vanilla-utils.js`.

Use lowercase, hyphenated page names such as `data-table.pug` and SCSS partials such as `_data-table.scss`. Reuse design tokens and scope app overlay styles to `body.app`. Match surrounding code; no formatter or linter is configured.

## Testing Guidelines

Run `npm test` with Node's built-in runner; name tests `test/*.test.js`. `npm run check` builds first. Tests cover asset references, chart loading, and Pug builds/watchers; no coverage threshold is configured. CI checks Node 22/24 and generated asset consistency. Check affected pages on desktop/mobile, exercise interactions, and inspect the console/network panel for errors. Shared layout changes require checking all pages; theme changes should cover light/dark modes and accent presets.

## Commit & Pull Request Guidelines

History uses descriptive, action-oriented subjects, such as “Restore calendar.html's inline FullCalendar style overrides”; release commits may start with a version. Follow that pattern and keep commits focused.

Pull requests should explain the problem and resulting behavior, link relevant issues, list validation performed, and include screenshots for visual changes. Include both source edits and regenerated assets.
